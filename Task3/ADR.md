### **Решение**

Для MVP выбрана следующая архитектура:

Интернет-банк дорабатывается командой банка без участия подрядчика. Добавляется новый модуль работы с депозитами. Для хранения ставок и заявок вводится новая таблица в MS SQL интернет-банка. Интеграция с АБС реализуется через очередь сообщений — чтобы не нагружать базу АБС прямыми вызовами.

Ставки по депозитам переносятся из Excel в АБС. Бэк-офис депозитов управляет ставками там же. Интернет-банк получает ставки из АБС через отдельный сервис.

Сайт передаёт заявки в систему кол-центра через API. Менеджер кол-центра видит заявку и перезванивает клиенту.

### **Альтернативы**

Прямая интеграция интернет-банка с АБС через API — отклонена, так как база АБС перегружена и прямые вызовы создают риск недоступности системы.

Реализация функционала смс через подрядчика интернет-банка — отклонена, так как увеличивает стоимость и сроки. Реализуем силами команды банка.

Хранение ставок в отдельном микросервисе — возможно на следующем этапе, в MVP избыточно.

**Недостатки, ограничения, риски**

- АБС масштабируется только вертикально — при росте нагрузки может стать узким местом
- Обмен данными между АБС и кредитным конвейером раз в сутки — не ускорить
- Текущая версия интернет-банка несовместима с Kafka — при переходе на микросервисы потребуется миграция
- Новый клиент всё равно должен прийти в отделение — полностью онлайн процесс невозможен на этапе MVP
